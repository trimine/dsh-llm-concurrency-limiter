# LLM并发限制器

**简体中文** | [English](./README.en.md)

为 [DeepSeek Harness](https://github.com/deepseek-ai) 提供图形化的 LLM 请求并发控制：按提供商、模型和当前对话设置上限，超出上限的请求进入等待队列。

- 包名：`dsh-llm-concurrency-limiter`
- 首个公开版本：`1.0.0`
- 仓库：https://github.com/trimine/dsh-llm-concurrency-limiter
- 许可证：[MIT](./LICENSE)

> 并发控制不等于 RPM/TPM 速率控制，不能保证消除 HTTP 429。本插件不会自动探测上游账户配额，也不会自动调整并发值。

## 功能

- 左侧 **LLM并发限制器** 面板统一管理配置。
- 自动列出 DSH 已注册的提供商；通过下拉列表添加主流提供商规则，或输入自定义提供商 ID。
- 设置全局总上限、提供商上限、模型上限及未单独配置提供商的默认上限。
- 对话输入栏 **并发限制** 按钮查看当前会话服务商、统一规则和运行状态，并设置仅针对该会话的额外上限。
- `X/Y 活跃 · Z 排队` 状态；有活跃请求时绿色，空闲时灰色。页面/打开的会话弹窗约每 1.5 秒刷新状态。
- 排队取消、超时及容量保护；统一配置由 DSH 配置编辑器保存。

## 兼容要求

- 面向 DSH `v0.2.2-rc.1`，包声明 `>=0.2.2-rc.1`；后续版本需按实际 API 验证，不能保证无限向后兼容。
- Node.js `^22.0.0 || >=24.0.0`（通常使用 DSH 自带运行时）。
- DSH Web/Desktop GUI，具有 `llm`、`webServer`，以及用于持久保存的 `configEditor`。
- 配置接口仅接受本机访问，不支持远程 GUI 配置。
- 当前界面主要为中文；本仓库提供中英文使用文档，不代表完整英文 UI。

## 使用

### 统一配置

1. 点击侧边栏 **LLM并发限制器**。
2. 为已接入的提供商输入并发上限，或从下拉列表/自定义 ID 添加规则。
3. 按需添加模型规则，设置默认提供商上限和全局上限。
4. 点击 **保存统一配置**，等待成功提示。

统一配置保存会走 DSH 正常配置重载流程。有请求执行或排队时保存会被拒绝，请待空闲后重试。保存错误会显示，不应把未保存的输入当作已生效配置。

添加提供商规则不会在 DSH 中创建 API 连接，也不会配置 API Key。自定义 ID 必须与 DSH 路由 ID 完全一致，不能只填显示名称。

移除独立规则意味着恢复默认并发值。若提供商仍在 DSH 中接入，它仍会自动出现在表格中；这不表示已删除的规则复活。

### 当前对话

点击输入栏 **并发限制**。悬停提示说明设置仅针对当前对话。弹窗读取当前 live Agent 的模型选择；无法识别时不猜测服务商。

- 输入正整数，为当前会话增加限制。
- 留空或填 `0` 恢复继承，不修改统一规则。
- 会话上限不能突破全局/提供商/模型上限。例如提供商上限为 3，会话填 8 也不能获得 8 个提供商槽位。
- 已有会话限流器忙碌时，修改会被拒绝，请空闲后重试。
- 覆盖按会话 ID 存储；切换到其他会话不会把该值带过去，切回原会话仍保留其覆盖。插件重载或 DSH 重启后会话覆盖清除。

弹窗的提供商运行状态是**该提供商跨会话共享状态**，不是仅当前会话的请求数。

## 配置参考

一般无需手动编辑。包初始配置为：

```json
{
  "globalConcurrency": null,
  "defaultProviderConcurrency": 5,
  "providers": {},
  "models": {
    "deepseek/deepseek-reasoner": 1,
    "deepseek-reasoner": 1
  },
  "maxQueueSize": 100,
  "queueTimeoutMs": 300000,
  "verbose": true
}
```

| 字段 | 含义 |
| --- | --- |
| `globalConcurrency` | 本 DSH 实例总请求上限；`null` 或 0 不设置总上限 |
| `defaultProviderConcurrency` | 未配置独立规则的每个提供商上限；默认 5 |
| `providers` | 提供商 ID → 正整数上限 |
| `models` | 模型规则 → 正整数上限 |
| `maxQueueSize` | 每个限流器的最大等待队列长度；默认 100 |
| `queueTimeoutMs` | 等待超时毫秒数；默认 300000，0 禁用超时 |
| `verbose` | 是否记录排队相关日志 |

模型规则优先匹配 `提供商ID/模型ID`，否则匹配纯模型 ID。纯模型 ID 规则在匹配它的提供商之间共享。明确区分 `deepseek` 与 `deepseek-official` 等实际 ID。

## 工作方式与限制

插件拦截 `llm/stream`，依次申请全局、会话、提供商和模型槽位，在流结束、异常或迭代退出时释放。当前计数包括已经占有某一层槽位、但仍在等待更内层槽位的请求，因此不应等同于上游正在生成的连接数。

- 限制的是 LLM 流式调用，不是所有工具执行数量、子代理进程数量或任务调度数量。
- 只能覆盖通过该 DSH 实例的 `llm/stream` 的调用，无法限制外部程序、其他 DSH 实例或绕过该事件的适配器。
- 并发上限不是上游账户总配额；API Key 被其他应用共用时仍可能触限。
- 降低上限不会强制中止正在执行的请求。
- 暂无自适应并发、上游配额自动检测或远程配置功能。

## 更新与卸载

更新前保存配置截图或备份，等待所有请求结束。通过 DSH 插件管理器更新；若提示包已安装，按其提示移除后安装目标版本。移除包可能影响其配置层，请勿依赖卸载操作保留配置。

暂停使用可在管理器中禁用插件。卸载后不再拦截新请求。不要在有重要任务时卸载/重载。

无需额外 npm 依赖：

当前包含 14 项回归测试，涵盖动态调限、队列取消/超时、卸载清理、接口校验、持久化调用、会话选择与隔离、提供商/模型叠加限制。20 个模拟请求在模型上限 2 时测得下游峰值为 2。

## 故障排查

- **保存失败/忙碌**：等待执行和排队请求结束后再保存，查看错误提示。
- **删除后仍显示提供商**：检查其是否仍已接入，以及是否已恢复默认而非保留独立规则。
- **状态延迟**：轮询有约 1.5 秒间隔；极短请求可能在两次采样之间完成。
- **当前服务商不显示**：需要可读取的 live Agent；打开实际会话后重试。
- **按钮界面旧**：先刷新 GUI；后端更新需按插件管理器提示加载，刷新页面不会重载后端。
- **仍遇到 429**：检查上游 RPM/TPM、额度、共享 API Key 及其他应用负载，不要仅提高并发。
